# Chapter 7. Strings

## 7.1 The String as a Data Type

`str` is an **immutable** sequence of Unicode characters.

**Python**

```python
s = "Hello"
s = 'Hello'            # the same
s = """several
lines"""               # with line breaks
```

**C++**

```cpp
// a string in double quotes
// 'Hello' in single quotes is an error: 'H' is a single char
string t = R"(several
// a "raw" multi-line literal
```

**JavaScript**

```javascript
let s = "Hello";
// the same
s = `several
// template literal, with line breaks
```

Immutability means that `s[0] = "h"` → `TypeError`.
Any "change" creates a **new** string.

**Three languages.** The C++ and JavaScript examples in this chapter use Latin letters so as not to get distracted by encodings: in C++ `std::string` stores **bytes**, and each Cyrillic letter takes 2 bytes in UTF-8, so `length()` and indices work with bytes rather than letters for Cyrillic text.

Immutability is a feature of Python and JavaScript (`s[0] = "x"` silently does nothing in JavaScript, and throws `TypeError` in strict mode). `std::string` in C++ is a **mutable** type: `s[0] = 'x'` is allowed.

### Escaping
| Notation | Character |
|----------|-----------|
| `\n` | new line |
| `\t` | tab |
| `\\` | backslash |
| `\"` `\'` | quotes |
| `r"C:\new"` | "raw" string, no escaping |

Escaping in C++ and JavaScript is the same (`\n`, `\t`, `\\`, `\"`, `\'`). A "raw" string: `R"(C:\new)"` in C++, `String.raw\`C:\new\`` in JavaScript.

## 7.2 Length, Indexing, Slices

**Python**

```python
s = "program"
len(s)        # 7
s[0]          # 'p'   — the first
s[-1]         # 'm'   — the last
s[2]          # 'o'
```

**C++**

```cpp
string s = "program";
s.length();            // 7     (також s.size())
// the first
// the last (s[s.size() - 1])
s[2];                  // 'o'
```

**JavaScript**

```javascript
const s = "program";
s.length;              // 7
// the first
// the last (s[s.length - 1])
s[2];                  // 'o'
```

In C++ the index `-1` does **not** mean "the last one": `s[-1]` is an out-of-bounds access (undefined behaviour). JavaScript has the `at` method for negative indices.

### Slices `s[start:stop:step]`

**Python**

```python
s[0:4]        # 'prog'    (stop is not included)
s[:4]         # 'prog'
s[4:]         # 'ram'
s[-4:]        # 'gram'
s[::2]        # 'porm'    (every second character)
s[::-1]       # 'margorp' — the string reversed
s[1:-1]       # without the first and last
```

**C++**

```cpp
// "prog"  (substr(position, length))
s.substr(4);                             // "ram"
s.substr(s.size() - 4);                  // "gram"
// without the first and last
// "margorp" — the string reversed
string every2;
for (size_t i = 0; i < s.size(); i += 2) every2 += s[i];   // "porm"
```

**JavaScript**

```javascript
// 'prog'  (the end is not included)
s.slice(4);                              // 'ram'
s.slice(-4);                             // 'gram'
// without the first and last
// 'margorp' — the string reversed
[...s].filter((_, i) => i % 2 === 0).join("");   // 'porm'
```

`substr` in C++ throws an `out_of_range` exception if the position is greater than the length — unlike Python slices, which are always "soft". `slice` in JavaScript, like a Python slice, never throws.

A slice **never raises IndexError** — out-of-range bounds are clipped.

## 7.4 Main Methods

### Case

**Python**

```python
"Text".upper()          # 'TEXT'
"Text".lower()          # 'text'
"some text".title()     # 'Some Text'
"text".capitalize()     # 'Text'
"TeXt".swapcase()       # 'tExT'
```

**C++**

```cpp
string t = "Text";
transform(t.begin(), t.end(), t.begin(), ::toupper);   // "TEXT"
transform(t.begin(), t.end(), t.begin(), ::tolower);   // "text"
string c = "text";
c[0] = toupper(c[0]);                                  // "Text"  (capitalize)
```

**JavaScript**

```javascript
"Text".toUpperCase();                                  // 'TEXT'
"Text".toLowerCase();                                  // 'text'
"some text".replace(/\b\p{L}/gu, ch => ch.toUpperCase());   // 'Some Text'  (title)
"text".charAt(0).toUpperCase() + "text".slice(1);      // 'Text'  (capitalize)
```

In C++ `toupper`/`tolower` work on a single character and only with Latin letters (ASCII); there are no ready-made `title()` and `swapcase()` — they are written with a loop.

### Checks (return bool)

**Python**

```python
"123".isdigit()    "abc".isalpha()    "a1".isalnum()
"  ".isspace()     "Abc".istitle()    "ABC".isupper()
"abc".startswith("a")    "abc".endswith("c")
```

**C++**

```cpp
string d = "123", w = "abc", sp = "  ";
all_of(d.begin(), d.end(), ::isdigit);     // true   — isdigit()
all_of(w.begin(), w.end(), ::isalpha);     // true   — isalpha()
all_of(w.begin(), w.end(), ::isalnum);     // true   — isalnum()
all_of(sp.begin(), sp.end(), ::isspace);   // true   — isspace()
all_of(w.begin(), w.end(), ::isupper);     // false  — isupper()
// true   (C++20)
// true   (C++20)
```

**JavaScript**

```javascript
/^\d+$/.test("123");                       // true   — isdigit()
/^\p{L}+$/u.test("abc");                   // true   — isalpha()
/^[\p{L}\d]+$/u.test("a1");                // true   — isalnum()
/^\s+$/.test("  ");                        // true   — isspace()
// true   — isupper() (approximately)
"abc".startsWith("a");                     // true
"abc".endsWith("c");                       // true
```

C++ and JavaScript have no ready-made check methods: use `<cctype>`/`<algorithm>` (C++) and regular expressions (JavaScript). `all_of` on an empty string gives `true`, whereas `"".isdigit()` in Python gives `False`.

### Trimming and replacing

**Python**

```python
"  text  ".strip()          # 'text'
"  text  ".lstrip()         # 'text  '
"xxtextxx".strip("x")       # 'text'
"banana".replace("a", "o")  # 'bonono'
"a-b-c".replace("-", "", 1) # 'ab-c'  (only the first one)
```

**C++**

```cpp
string t = "  text  ";
t.erase(0, t.find_first_not_of(' '));      // lstrip: "text  "
t.erase(t.find_last_not_of(' ') + 1);      // rstrip: "text"
string k = "banana";
// "bonono" — all occurrences of a character
string h = "a-b-c";
// "ab-c" — only the first one
```

**JavaScript**

```javascript
"  text  ".trim();                         // 'text'
"  text  ".trimStart();                    // 'text  '
"xxtextxx".replace(/^x+|x+$/g, "");        // 'text'
"banana".replaceAll("a", "o");             // 'bonono'
// 'ab-c' — a string pattern replaces only the first one
```

C++ has no standard `strip` function — use `find_first_not_of`/`find_last_not_of`.

### Splitting and joining

**Python**

```python
"1 2 3".split()            # ['1', '2', '3']
"a,b,c".split(",")         # ['a', 'b', 'c']
"a\nb".splitlines()        # ['a', 'b']
" ".join(["a", "b", "c"])  # 'a b c'
```

**C++**

```cpp
vector<string> parts;
string tok;

istringstream iss("1 2 3");
// split() on whitespace: {"1","2","3"}

istringstream csv("a,b,c");
while (getline(csv, tok, ',')) parts.push_back(tok);   // split(","): {"a","b","c"}

string joined;
for (size_t i = 0; i < parts.size(); ++i) {      // join(" ")
    if (i > 0) joined += " ";
    joined += parts[i];
}
```

**JavaScript**

```javascript
"1 2 3".split(/\s+/);                      // ['1', '2', '3']
"a,b,c".split(",");                        // ['a', 'b', 'c']
// ['a', 'b']   (counterpart of splitlines)
// 'a b c'      (an array method!)
```

C++ has no ready-made `split` and `join` — they are built from `istringstream`/`getline` and a loop. In JavaScript `join` is a method of the **array**, not of the separator string.

`join` works only with a list of **strings** — numbers must be converted:

**Python**

```python
" ".join(str(x) for x in [1, 2, 3])    # '1 2 3'
```

**C++**

```cpp
vector<int> v = {1, 2, 3};
string out;
for (size_t i = 0; i < v.size(); ++i) {
    if (i > 0) out += " ";
    // number → string
}
```

**JavaScript**

```javascript
[1, 2, 3].map(String).join(" ");           // '1 2 3'
// '1 2 3' — join converts numbers itself
```

### Alignment

**Python**

```python
"5".zfill(3)        # '005'
"ab".ljust(5, ".")  # 'ab...'
"ab".rjust(5, ".")  # '...ab'
"ab".center(6, "-") # '--ab--'
```

**C++**

```cpp
string t = "5", u = "ab";
// "005"   zfill (t is shorter than 3)
u + string(5 - u.size(), '.');             // "ab..."   ljust
string(5 - u.size(), '.') + u;             // "...ab"   rjust
```

**JavaScript**

```javascript
"5".padStart(3, "0");                      // '005'
"ab".padEnd(5, ".");                       // 'ab...'
"ab".padStart(5, ".");                     // '...ab'
// there is no center in JavaScript — build it by hand
```

## 7.6 Character Codes

**Python**

```python
ord("A")       # 65
chr(65)        # 'A'
ord("а")       # 1072  (the Cyrillic 'а' — not the Latin 'a'!)
```

**C++**

```cpp
int('A');                // 65
char(65);                  // 'A'
// 1072  (the Cyrillic 'а' of type char32_t — not the Latin 'a'!)
```

**JavaScript**

```javascript
"A".charCodeAt(0);         // 65
String.fromCharCode(65);   // 'A'
// 1072  (the Cyrillic 'а' — not the Latin 'a'!)
```

In C++ `char` is both a character and a small integer, so `'a' + 1` equals 98, while `char('a' + 1)` is `'b'`.

The Caesar cipher for the Latin alphabet:

**Python**

```python
def caesar(ch, k):
    if "a" <= ch <= "z":
        return chr((ord(ch) - ord("a") + k) % 26 + ord("a"))
    return ch
```

**C++**

```cpp
char caesar(char ch, int k) {
    if ('a' <= ch && ch <= 'z') {
        // + 26 — for a negative k
    }
    return ch;
}
```

**JavaScript**

```javascript
function caesar(ch, k) {
  if ("a" <= ch && ch <= "z") {
    const shifted = (ch.charCodeAt(0) - 97 + k) % 26;
    // + 26 — for a negative k
  }
  return ch;
}
```

In C++ and JavaScript `%` of a negative number gives a negative result, so 26 is added for a negative shift — in Python `%` is always non-negative.

## 7.7 Typical Algorithms

### Palindrome

**Python**

```python
t = "".join(c.lower() for c in s if c.isalnum())
print(t == t[::-1])
```

**C++**

```cpp
string t;
for (char c : s) {
    if (isalnum((unsigned char)c)) t += tolower((unsigned char)c);
}
string r(t.rbegin(), t.rend());
cout << boolalpha << (t == r) << endl;
```

**JavaScript**

```javascript
const t = [...s].filter(c => /[\p{L}\d]/u.test(c)).map(c => c.toLowerCase()).join("");
console.log(t === [...t].reverse().join(""));
```

### Counting vowels

**Python**

```python
vowels = "aeiou"
k = sum(1 for c in s.lower() if c in vowels)
```

**C++**

```cpp
string vowels = "aeiou";
int k = 0;
for (char c : s) {
    if (vowels.find(tolower((unsigned char)c)) != string::npos) k++;
}
```

**JavaScript**

```javascript
const vowels = "aeiou";
const k = [...s.toLowerCase()].filter(c => vowels.includes(c)).length;
```

### Longest word

**Python**

```python
words = s.split()
longest = max(words, key=len)
```

**C++**

```cpp
istringstream iss(s);
string w, longest;
while (iss >> w) {
    if (w.size() > longest.size()) longest = w;
}
```

**JavaScript**

```javascript
const words = s.split(/\s+/).filter(Boolean);
const longest = words.reduce((a, b) => (b.length > a.length ? b : a), "");
```

### Number of words

**Python**

```python
print(len(s.split()))
```

**C++**

```cpp
istringstream iss(s);
string w;
int count = 0;
while (iss >> w) count++;
cout << count << endl;
```

**JavaScript**

```javascript
console.log(s.split(/\s+/).filter(Boolean).length);
```

**Python**

```python
print(" ".join(s.split()))
```

**C++**

istringstream iss(s);
string w, res;

    if (!res.empty()) res += " ";

## 7.8 Why Concatenation in a Loop Is Bad

**Python**

```python
# bad: O(n²), a new string is created each time
res = ""
for ch in s:
    res += ch

# good: O(n)
res = "".join(parts)
```

**C++**

```cpp
// in C++ += on std::string is amortised O(1), because the string is mutable
string res;
for (char ch : s) {
    res += ch;
}

// the same when assembling ready-made parts
ostringstream os;
for (const string &p : parts) os << p;
string res2 = os.str();
```

**JavaScript**

```javascript
// modern engines optimise +=, but join is more reliable
let res = "";
for (const ch of s) {
  res += ch;
}

const res2 = parts.join("");
```

Concatenation in a loop is slow precisely in Python (and similar languages with immutable strings); in C++ `s += ch` takes amortised O(1), while `s = s + ch` creates a copy each time.
