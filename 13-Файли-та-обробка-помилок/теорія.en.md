# Chapter 13. Files and Error Handling

## 13.1 Why Files

Data in variables lives only while the program runs.
A file provides **persistent storage**: the data remains
after the program ends.

## 13.2 Opening a File

**Python**

```python
f = open("data.txt", "r", encoding="utf-8")
...
f.close()          # mandatory!
```

**C++**

```cpp
// opening for reading (<fstream>)
// ...
// optional: the destructor closes the file itself
```

**JavaScript**

```javascript
const fs = require("fs");

const fd = fs.openSync("data.txt", "r");
// ...
// mandatory!
```

### The right way — the `with` context manager

**Python**

```python
with open("data.txt", "r", encoding="utf-8") as f:
    text = f.read()
# the file is closed automatically, even if an error occurred
```

**C++**

```cpp
string text;
{
    ifstream f("data.txt");
    stringstream buf;
    buf << f.rdbuf();
    text = buf.str();
// f is closed automatically at the end of the block (RAII)
```

**JavaScript**

```javascript
// opening and closing happen inside the call
```

In C++ the role of `with` is played by the object lifetime itself: when an `ifstream` variable goes out of scope, the file is closed (the **RAII** idiom).

### Opening Modes

| Mode | Action | If the file does not exist | If it exists |
|------|--------|----------------------------|--------------|
| `"r"` | read | `FileNotFoundError` | reads |
| `"w"` | write | creates it | **erases the contents!** |
| `"a"` | append | creates it | appends to the end |
| `"x"` | create | creates it | `FileExistsError` |
| `"r+"` | read+write | error | does not erase |
| `"rb"` / `"wb"` | binary | | for images, archives |

Counterparts in C++ (`<fstream>`) and Node.js (`fs`):

| Python | C++ | Node.js |
|--------|-----|---------|
| `"r"` | `ifstream` (`ios::in`) | `readFileSync` (`"r"`) |
| `"w"` | `ofstream` (`ios::out`) | `writeFileSync` (`"w"`) |
| `"a"` | `ofstream f(path, ios::app)` | `appendFileSync` (`"a"`) |
| `"x"` | no direct counterpart | `"wx"` |
| `"r+"` | `fstream` (`ios::in` + `ios::out`) | `"r+"` |
| `"rb"` / `"wb"` | `ios::binary` | `Buffer` (without the `"utf8"` argument) |

In C++ a file is a stream of bytes, there is no encoding conversion: Ukrainian text in UTF-8 is simply read and written as is. In Node.js, without the `"utf8"` argument the `fs` functions return a `Buffer` rather than a string.

**Always specify `encoding="utf-8"`** — otherwise the behavior depends
on the operating system, and non-ASCII text (such as Ukrainian) may get "broken".

## 13.3 Reading

**Python**

```python
with open("f.txt", encoding="utf-8") as f:
    text = f.read()              # the whole file as one string

    lines = f.readlines()        # a list of lines (with \n at the end)

    line = f.readline()          # one line

    for line in f:               # BEST: line by line, memory-friendly

    // getline already strips \n
}
```

## 13.4 Writing

**Python**

```python
with open("out.txt", "w", encoding="utf-8") as f:
    f.write("first line\n")         # you must write \n yourself!
    f.writelines(["a\n", "b\n"])
    print("via print", file=f)       # print adds \n itself
```

**C++**

```cpp
ofstream f("out.txt");
// you must write \n yourself (or endl)
f << "a\n" << "b\n";
// << accepts numbers too: f << 42
```

**JavaScript**

```javascript
// overwrites the file (mode "w"), \n — yourself
// append (mode "a")
fs.appendFileSync("out.txt", "via print\n");
```

The `<<` stream in C++ converts numbers to text itself; in Node.js `fs` accepts only strings (or a `Buffer`), so numbers are converted with `String(n)` or a template string.

`write()` accepts **only a string** — convert numbers with `str()`
or an f-string.

## 13.5 The pathlib Module (the Modern Approach)

**Python**

```python
from pathlib import Path

p = Path("data.txt")
p.exists()                     # whether it exists
p.is_file()  p.is_dir()
p.suffix                       # '.txt'
p.stem                         # 'data'
p.stat().st_size               # size in bytes

p.write_text("text", encoding="utf-8")
text = p.read_text(encoding="utf-8")

for f in Path(".").glob("*.txt"):     # iterating over files
    print(f.name)
```

**C++**

```cpp
// header <filesystem>, C++17

fs::path p = "data.txt";
// whether it exists
fs::is_regular_file(p);              // is_file
fs::is_directory(p);                 // is_dir
p.extension();                       // ".txt"
p.stem();                            // "data"
// size in bytes

// iterating over files
    if (e.path().extension() == ".txt") {
        cout << e.path().filename() << endl;
    }
}
```

**JavaScript**

```javascript
const fs = require("fs");
const path = require("path");

// whether it exists
fs.statSync("data.txt").isFile();             // is_file
fs.statSync(".").isDirectory();               // is_dir
path.extname("data.txt");                     // '.txt'
path.parse("data.txt").name;                  // 'data'
// size in bytes

// iterating over files
  if (f.endsWith(".txt")) {
    console.log(f);
  }
}
```

## 13.6 CSV — Tables in a Text File

**Python**

```python
import csv

with open("t.csv", "w", newline="", encoding="utf-8") as f:
    w = csv.writer(f)
    w.writerow(["surname", "score"])
    w.writerows([["Koval", 74], ["Tkach", 58]])

with open("t.csv", encoding="utf-8") as f:
    for row in csv.reader(f):
        print(row)                    # a list of strings

with open("t.csv", encoding="utf-8") as f:
    for row in csv.DictReader(f):     # a dictionary keyed by the headers
        print(row["surname"])
```

**C++**

```cpp
{
    ofstream out("t.csv");
    out << "surname,score\n";
    out << "Koval,74\n" << "Tkach,58\n";
}

ifstream in("t.csv");
string line;
while (getline(in, line)) {
    vector<string> row;
    stringstream ss(line);
    // a list of strings
    cout << row[0] << endl;
}
```

**JavaScript**

```javascript
fs.writeFileSync("t.csv", ["surname,score", "Koval,74", "Tkach,58"].join("\n") + "\n");

const rows = fs.readFileSync("t.csv", "utf8").trim().split("\n").map(line => line.split(","));
for (const row of rows) {
  // a list of strings
}

// counterpart of DictReader: a dictionary keyed by the headers
const records = body.map(r => Object.fromEntries(r.map((v, i) => [header[i], v])));
for (const rec of records) {
  console.log(rec.surname);
}
```

Such parsing works only for simple CSV: fields with commas or quotes need a library (for example, `csv-parse` for Node.js). Numbers are read as strings too — they have to be converted (`stoi`, `Number`).

## 13.7 JSON — Structured Data

**Python**

```python
import json

data = {"name": "Ivan", "scores": [92, 74]}

with open("d.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)

with open("d.json", encoding="utf-8") as f:
    data = json.load(f)

s = json.dumps(data, ensure_ascii=False)     # to a string
data = json.loads(s)                          # from a string
```

**C++**

```cpp
// a third-party header (nlohmann/json)
using json = nlohmann::json;

json data = {{"name", "Ivan"}, {"scores", {92, 74}}};

// writing with indentation
ifstream f("d.json");
data = json::parse(f);

// to a string
// from a string
```

**JavaScript**

```javascript
let data = { name: "Ivan", scores: [92, 74] };

fs.writeFileSync("d.json", JSON.stringify(data, null, 2));
data = JSON.parse(fs.readFileSync("d.json", "utf8"));

// to a string
// from a string
```

The C++ standard library has no JSON support — a third-party one is used (`nlohmann/json`, `RapidJSON`). In JavaScript `JSON` is a built-in object, and it writes Unicode as is (a parameter like `ensure_ascii` is not needed).

`ensure_ascii=False` — so that non-ASCII letters (such as Ukrainian ones) stay letters
and not escape sequences like `\u0456`.

## 13.8 Exceptions

An **exception** is an object that describes a runtime error
and interrupts the normal flow of the program.

### Main built-in exceptions

| Exception | When it occurs |
|-----------|----------------|
| `ValueError` | the right type, a wrong value: `int("abc")` |
| `TypeError` | a wrong type: `"a" + 1` |
| `ZeroDivisionError` | division by zero |
| `IndexError` | an index outside the list |
| `KeyError` | no such key in a dictionary |
| `FileNotFoundError` | the file was not found |
| `PermissionError` | no permission for the file |
| `AttributeError` | no such attribute/method |
| `NameError` | the variable is not defined |
| `UnicodeDecodeError` | wrong file encoding |
| `KeyboardInterrupt` | Ctrl+C |

What happens in similar situations in C++ and JavaScript:

| Python | C++ | JavaScript |
|--------|-----|------------|
| `ValueError` | `invalid_argument` (`stoi("abc")`) | `NaN` — no exception |
| `TypeError` | a compilation error (static typing) | `TypeError` |
| `ZeroDivisionError` | `int`: undefined behaviour, a crash; `double`: `inf` | `Infinity` — no exception |
| `IndexError` | `out_of_range` (`at`) or undefined behaviour (`[]`) | `undefined` — no exception |
| `KeyError` | `out_of_range` (`map::at`) | `undefined` — no exception |
| `FileNotFoundError` | the stream is in a failed state (`if (!f)`) | `Error` with `code: "ENOENT"` |
| `AttributeError` | a compilation error | `TypeError` or `undefined` |
| `NameError` | a compilation error | `ReferenceError` |

Conclusion: in C++ the compiler detects a considerable part of the errors, and the others lead to undefined behaviour; JavaScript often "silently" returns `NaN` or `undefined`, so results have to be checked by hand.

## 13.9 The try / except Construct

**Python**

```python
try:
    n = int(input("Number: "))
    r = 100 / n
except ValueError:
    print("That is not a number")
except ZeroDivisionError:
    print("Zero is not allowed")
except (TypeError, KeyError) as e:        # several types together
    print(f"Error: {e}")
else:
    print(f"Result: {r}")                 # if there was NO exception
finally:
    print("Always runs")                  # cleaning up resources
```

**C++**

```cpp
try {
    cout << "Number: ";
    string s;
    cin >> s;
    // throws invalid_argument
    if (n == 0) {
        // integer division by zero throws nothing — we check ourselves
    }
    double r = 100.0 / n;
    cout << "Result: " << r << endl;
} catch (const invalid_argument &) {
    cout << "That is not a number" << endl;
} catch (const domain_error &) {
    cout << "Zero is not allowed" << endl;
// the base type of standard exceptions
    cout << "Error: " << e.what() << endl;
}
// there is no finally in C++: resources are released by destructors (RAII)
```

**JavaScript**

```javascript
try {
  const n = Number(lines[0]);
  if (Number.isNaN(n)) throw new TypeError("That is not a number");
  if (n === 0) throw new RangeError("Zero is not allowed");
  console.log(`Result: ${100 / n}`);
// a single catch block: the type is checked by hand
  if (e instanceof TypeError || e instanceof RangeError) {
    console.log(e.message);
  } else {
    // unknown errors are not swallowed
  }
} finally {
  console.log("Always runs");
}
```

C++ and JavaScript have no `else` block for `try` — code that must run only when there is no exception is simply placed at the end of the `try`. JavaScript has only one `catch`, not several by type.

Order of blocks: `try` → `except` → `else` → `finally`.

### What not to do

**Python**

```python
except:                 # catches EVERYTHING, even Ctrl+C — bad
    pass                # the error is swallowed without a trace — very bad

except Exception as e:  # acceptable if you log the error
    print(f"Failure: {e}")
```

**C++**

```cpp
try { risky(); }
// catches EVERYTHING — bad
    // the error is swallowed without a trace — very bad
}

try { risky(); }
// acceptable if you log the error
    cerr << "Failure: " << e.what() << endl;
}
```

**JavaScript**

```javascript
try { risky(); }
// the error is swallowed without a trace — very bad
}

try { risky(); }
// acceptable if you log the error
  console.error(`Failure: ${e.message}`);
}
```

Catch the **specific** exceptions you know how to handle.

## 13.10 Raising Exceptions

**Python**

```python
def sqrt(x):
    if x < 0:
        raise ValueError(f"negative argument: {x}")
    return x ** 0.5
```

**C++**

```cpp
double my_sqrt(double x) {
    if (x < 0) {
        throw invalid_argument("negative argument: " + to_string(x));
    }
    return sqrt(x);
}
```

**JavaScript**

```javascript
function sqrt(x) {
  if (x < 0) {
    throw new RangeError(`negative argument: ${x}`);
  }
  return x ** 0.5;
}
```

In C++ and JavaScript an exception is raised with the `throw` operator (not `raise`). In C++ a value of any type can be thrown, but the convention is an object derived from `std::exception`.

### A custom exception

**Python**

```python
class InvalidGradeError(ValueError):
    """A score outside the range 0..100."""


def check(score):
    if not 0 <= score <= 100:
        raise InvalidGradeError(f"score {score} is outside 0..100")
```

**C++**

```cpp
// A score outside the range 0..100.
class InvalidGradeError : public invalid_argument {
public:
    using invalid_argument::invalid_argument;
};

void check(int score) {
    if (!(0 <= score && score <= 100)) {
        throw InvalidGradeError("score " + to_string(score) + " is outside 0..100");
    }
}
```

**JavaScript**

```javascript
// A score outside the range 0..100.
class InvalidGradeError extends RangeError {
  constructor(score) {
    super(`score ${score} is outside 0..100`);
    this.name = "InvalidGradeError";
  }
}

function check(score) {
  if (!(0 <= score && score <= 100)) {
    throw new InvalidGradeError(score);
  }
}
```

### Re-raising

**Python**

```python
try:
    risky()
except ValueError as e:
    log(e)
    raise                 # pass the error on
```

**C++**

```cpp
try {
    risky();
} catch (const invalid_argument &e) {
    logmsg(e.what());
    // pass the error on
}
```

**JavaScript**

```javascript
try {
  risky();
} catch (e) {
  log(e);
  // pass the error on
}
```

## 13.11 A Typical Pattern: Robust Input Reading

**Python**

```python
def read_int(prompt: str) -> int:
    while True:
        try:
            return int(input(prompt))
        except ValueError:
            print("Enter an integer.")
```

**C++**

```cpp
int read_int(const string &prompt) {
    while (true) {
        cout << prompt;
        string s;
        cin >> s;
        try {
            return stoi(s);
        } catch (const invalid_argument &) {
            cout << "Enter an integer." << endl;
        }
    }
}
```

**JavaScript**

```javascript
const readline = require("readline/promises");
const rl = readline.createInterface({ input: process.stdin, output: process.stdout });

async function readInt(prompt) {
  while (true) {
    const s = await rl.question(prompt);
    const n = Number(s);
    // Number("abc") gives NaN, not an exception
      return n;
    }
    console.log("Enter an integer.");
  }
}
```

`stoi("12abc")` in C++ returns 12 without an error (it parses only the beginning of the string) — for a strict check, use the second argument `stoi(s, &pos)` and compare `pos` with the length of the string.

## 13.12 A Pattern: Safe File Handling

**Python**

```python
def load_numbers(path: str) -> list[int]:
    try:
        with open(path, encoding="utf-8") as f:
            return [int(x) for x in f.read().split()]
    except FileNotFoundError:
        print(f"File {path} not found")
        return []
    except ValueError as e:
        print(f"The file contains more than just numbers: {e}")
        return []
```

**C++**

```cpp
vector<int> load_numbers(const string &path) {
    ifstream f(path);
    if (!f) {
        cout << "File " << path << " not found" << endl;
        return {};
    }
    try {
        vector<int> nums;
        for (string tok; f >> tok; ) nums.push_back(stoi(tok));
        return nums;
    } catch (const invalid_argument &e) {
        cout << "The file contains more than just numbers: " << e.what() << endl;
        return {};
    }
}
```

**JavaScript**

```javascript
function loadNumbers(path) {
  try {
    const text = fs.readFileSync(path, "utf8");
    const nums = text.split(/\s+/).filter(Boolean).map(Number);
    if (nums.some(Number.isNaN)) {
      throw new TypeError("not a number");
    }
    return nums;
  } catch (e) {
    if (e.code === "ENOENT") {
      console.log(`File ${path} not found`);
    } else {
      console.log(`The file contains more than just numbers: ${e.message}`);
    }
    return [];
  }
}
```

## 13.13 assert — Checking Assumptions

**Python**

```python
assert n > 0, "n must be positive"
```

**C++**

```cpp
assert(n > 0 && "n must be positive");     // <cassert>
```

**JavaScript**

```javascript
const assert = require("assert");
assert(n > 0, "n must be positive");
```

In C++ `assert` is disabled by the `NDEBUG` macro (by default in a release build) — just as `python -O` disables `assert`. In JavaScript use the `assert` module in Node.js: `console.assert` only prints a message and does not stop the program.

It is used for **internal invariants** and tests,
not for validating user data (it is disabled by the `-O` flag).
