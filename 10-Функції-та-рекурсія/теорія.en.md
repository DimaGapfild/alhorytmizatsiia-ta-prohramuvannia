# Chapter 10. Functions and Recursion

## 10.1 Purpose of Functions

A **function (subroutine)** is a named fragment of code that can be
called many times with different data.

What functions give you:
- **reuse** — the code is written once;
- **decomposition** — a big problem is split into small ones;
- **abstraction** — the user cares about *what* the function does, not *how*;
- **testability** — a function is easy to test in isolation.

## 10.2 Declaration and Call

**Python**

```python
def area(a, b):            # def, name, parameters, colon
    """Area of a rectangle."""   # docstring
    return a * b           # returning a value

s = area(3, 4)             # a call, arguments 3 and 4
```

**C++**

```cpp
// Area of a rectangle.
// result type, name, parameters with types
    // returning a value
}

// a call, arguments 3 and 4
```

**JavaScript**

```javascript
/** Area of a rectangle. */
// function, name, parameters (no types)
  // returning a value
}

// a call, arguments 3 and 4
```

The arrow form in JavaScript: `const area = (a, b) => a * b;`.

A **parameter** is a name in the declaration. An **argument** is a value at the call.

A function without `return` returns `None`.
`return` ends the function immediately.

In C++ the result type is written before the function name; if no value is returned — `void`. A function must be declared (or defined) **before** the place of the call; for this a prototype is written: `int area(int a, int b);`. In JavaScript a function without `return` returns `undefined`; `function` declarations are "hoisted", so such a function can be called even before the line of its declaration.

**Python**

```python
def sign(x):
    if x > 0:
        return 1
    if x < 0:
        return -1
    return 0
```

**C++**

```cpp
int sign(int x) {
    if (x > 0) {
        return 1;
    }
    if (x < 0) {
        return -1;
    }
    return 0;
}
```

**JavaScript**

```javascript
function sign(x) {
  if (x > 0) {
    return 1;
  }
  if (x < 0) {
    return -1;
  }
  return 0;
}
```

## 10.3 Kinds of Parameters

**Python**

```python
def f(a, b=10, *args, **kwargs):
    ...
```

**C++**

```cpp
// default values come at the end of the list
    // ...
}

// counterpart of *args: sum_all({1, 2, 3})
    int s = 0;
    for (int x : nums) s += x;
    return s;
}
```

**JavaScript**

```javascript
// ...args is the counterpart of *args (an array)
  // ...
}

// "named" parameters via object destructuring
  // ...
}
// the order does not matter
```

| Kind | Example | Description |
|------|---------|-------------|
| positional | `f(1, 2)` | by order |
| keyword | `f(a=1, b=2)` | by name, order does not matter |
| with a default value | `def f(b=10)` | may be omitted |
| `*args` | `def f(*nums)` | any number of positional arguments (a tuple) |
| `**kwargs` | `def f(**opts)` | any number of keyword arguments (a dictionary) |

C++ has no named arguments — parameters are passed by position only; but it has **overloading**: several functions with the same name but different parameter lists (`int area(int a)` and `int area(int a, int b)`). JavaScript has no overloading: the last declaration with the same name overrides the previous ones, and "named" parameters are imitated by passing an object.

### The danger of a mutable default value

**Python**

```python
def bad(x, acc=[]):      # MISTAKE: the list is created ONCE
    acc.append(x)
    return acc

bad(1)   # [1]
bad(2)   # [1, 2]  — not [2]!

def good(x, acc=None):   # correct
    if acc is None:
        acc = []
    acc.append(x)
    return acc
```

**C++**

```cpp
// the default value is evaluated at EVERY call
    acc.push_back(x);
    return acc;
}
// good(1) -> {1}; good(2) -> {2}: Python's trap does not occur here
```

**JavaScript**

```javascript
// a new array is created at EVERY call
  acc.push(x);
  return acc;
}
f(1);                                      // [1]
// [2] — Python's trap does not occur here
```

In C++ and JavaScript the default value is evaluated at each call, so no shared "accumulator" appears.

## 10.5 Scope

The **LEGB** rule: Local → Enclosing → Global → Built-in.

**Python**

```python
x = 10              # global

def f():
    x = 5           # LOCAL, a different variable
    print(x)        # 5

f()
print(x)            # 10
```

**C++**

```cpp
// global

void f() {
    // LOCAL, a different variable
    cout << x << endl;         // 5
}

int main() {
    f();
    cout << x << endl;         // 10
}
```

**JavaScript**

```javascript
// global

function f() {
  // LOCAL, a different variable
  console.log(x);              // 5
}

f();
console.log(x);                // 10
```

In C++ and JavaScript the scope is determined by the block `{ }`: a variable declared in a block exists only in it.

**Python**

```python
def g():
    global x
    x = 99          # changes the global one
```

**C++**

```cpp
void g() {
    // changes the global one (no global keyword is needed)
    // if a local x exists, the global one is written as ::x
}
```

**JavaScript**

```javascript
function g() {
  // changes the outer variable (if there is no local x)
}
```

Without a local variable of the same name, C++ and JavaScript find the outer one themselves; assigning to it changes it. So it is easier to accidentally "hit" a global variable here than in Python.

Using `global` is considered poor style — it is better to pass
data via parameters and return the result.

### Mutable arguments

**Python**

```python
def add_item(lst):
    lst.append(1)      # CHANGES the caller's list!

a = []
add_item(a)
print(a)               # [1]
```

**C++**

```cpp
// & — passing by reference
    // CHANGES the caller's vector!
}

// without & — works with a copy
    // nothing changes outside
}

int main() {
    vector<int> a;
    add_item(a);
    cout << a.size() << endl;          // 1
}
```

**JavaScript**

```javascript
function addItem(lst) {
  // CHANGES the caller's array!
}

const a = [];
addItem(a);
console.log(a);                        // [ 1 ]
```

In C++ parameters are **copied** by default; for a function to change the original, a reference (`&`) is used. For large objects that are only read, `const vector<int> &v` is written to avoid copying. In JavaScript numbers and strings are passed as values, while arrays and objects are passed as references (as in Python).

Numbers and strings are immutable — they cannot be changed from inside a function.

## 10.6 Recursion

**Recursion** is a function calling itself.

Required components:
1. the **base case** — a termination condition without recursion;
2. the **step** — a call to itself with "smaller" data that approaches the base case.

**Python**

```python
def factorial(n):
    if n <= 1:          # base case
        return 1
    return n * factorial(n - 1)    # step
```

**C++**

```cpp
long long factorial(int n) {
    // base case
        return 1;
    }
    // step
}
```

**JavaScript**

```javascript
function factorial(n) {
  // base case
    return 1;
  }
  // step
}
```

`long long` holds a factorial only up to 20!; integers of the JavaScript `number` type are guaranteed exact only up to 2⁵³ (roughly 18!). Beyond that you need `BigInt`.

The call tree for `factorial(4)`:
```
factorial(4) = 4 * factorial(3)
               3 * factorial(2)
                   2 * factorial(1)
                       1           ← base case
= 4*3*2*1 = 24
```

### Examples

**Sum of digits**

**Python**

```python
def digit_sum(n):
    return n if n < 10 else n % 10 + digit_sum(n // 10)
```

**C++**

```cpp
int digit_sum(int n) {
    return n < 10 ? n : n % 10 + digit_sum(n / 10);
}
```

**JavaScript**

```javascript
function digitSum(n) {
  return n < 10 ? n : (n % 10) + digitSum(Math.floor(n / 10));
}
```

**Fibonacci (naive — exponentially slow)**

**Python**

```python
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)
```

**C++**

```cpp
long long fib(int n) {
    return n < 2 ? n : fib(n - 1) + fib(n - 2);
}
```

**JavaScript**

```javascript
function fib(n) {
  return n < 2 ? n : fib(n - 1) + fib(n - 2);
}
```

**Fibonacci with memoization (fast)**

**Python**

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)
```

**C++**

```cpp
long long fib(int n) {
    // the cache persists between calls
    if (n < 2) return n;
    auto it = memo.find(n);
    if (it != memo.end()) return it->second;
    return memo[n] = fib(n - 1) + fib(n - 2);
}
```

**JavaScript**

```javascript
const memo = new Map();

function fib(n) {
  if (n < 2) return n;
  if (memo.has(n)) return memo.get(n);
  const r = fib(n - 1) + fib(n - 2);
  memo.set(n, r);
  return r;
}
```

There is no ready-made `lru_cache` decorator in C++ and JavaScript — the cache (`unordered_map`, `Map`) is written by hand.

**Fast exponentiation — O(log n)**

**Python**

```python
def power(a, n):
    if n == 0:
        return 1
    if n % 2 == 0:
        half = power(a, n // 2)
        return half * half
    return a * power(a, n - 1)
```

**C++**

```cpp
long long power(long long a, int n) {
    if (n == 0) {
        return 1;
    }
    if (n % 2 == 0) {
        long long half = power(a, n / 2);
        return half * half;
    }
    return a * power(a, n - 1);
}
```

**JavaScript**

```javascript
function power(a, n) {
  if (n === 0) {
    return 1;
  }
  if (n % 2 === 0) {
    const half = power(a, n / 2);
    return half * half;
  }
  return a * power(a, n - 1);
}
```

**Towers of Hanoi**

**Python**

```python
def hanoi(n, src, dst, tmp):
    if n == 0:
        return
    hanoi(n - 1, src, tmp, dst)
    print(f"{src} -> {dst}")
    hanoi(n - 1, tmp, dst, src)
```

**C++**

```cpp
void hanoi(int n, const string &src, const string &dst, const string &tmp) {
    if (n == 0) {
        return;
    }
    hanoi(n - 1, src, tmp, dst);
    cout << src << " -> " << dst << endl;
    hanoi(n - 1, tmp, dst, src);
}
```

**JavaScript**

```javascript
function hanoi(n, src, dst, tmp) {
  if (n === 0) {
    return;
  }
  hanoi(n - 1, src, tmp, dst);
  console.log(`${src} -> ${dst}`);
  hanoi(n - 1, tmp, dst, src);
}
```

## 10.7 Recursion vs Iteration

| | Recursion | Loop |
|---|---|---|
| readability for trees/fractals | better | worse |
| memory cost | O(depth) — the stack | O(1) |
| speed | lower | higher |
| risk | `RecursionError` | an infinite loop |

Depth limit: `sys.getrecursionlimit()` — 1000 by default.
`sys.setrecursionlimit(10000)` raises it (carefully!).

In C++ the limit is not fixed: the depth depends on the stack size (usually in the order of tens of thousands of calls), after which the program crashes (*stack overflow*). In JavaScript too deep a recursion throws `RangeError: Maximum call stack size exceeded` (in the order of 10,000 calls in Node.js).

**Any recursion can be rewritten as a loop**, but not always easily.

## 10.8 Lambda Functions

**Python**

```python
square = lambda x: x ** 2        # a short anonymous function
sorted(words, key=lambda w: len(w))
sorted(pairs, key=lambda p: (-p[1], p[0]))
```

**C++**

```cpp
// lambda expression (C++11)

sort(words.begin(), words.end(),
     [](const string &a, const string &b) { return a.size() < b.size(); });

sort(pairs.begin(), pairs.end(),
     [](const pair<string, int> &p, const pair<string, int> &q) {
         return p.second != q.second ? p.second > q.second : p.first < q.first;
     });
```

**JavaScript**

```javascript
// an arrow function

words.sort((a, b) => a.length - b.length);

pairs.sort((p, q) => q[1] - p[1] || p[0].localeCompare(q[0]));
```

`sort` in C++ and JavaScript changes the container in place, while Python's `sorted` creates a new list.

For anything more complex than a single expression, use a regular `def`.

## 10.9 Rules for a Good Function

1. Does **one** thing, and this is clear from the name.
2. The name is a verb or `is_`/`get_`/`count_` + a noun.
3. No more than 3–4 parameters.
4. Has a docstring: what it does, what it takes, what it returns.
5. Does not print what it should return (`return`, not `print`).
6. Does not change its arguments without an explicit need.
