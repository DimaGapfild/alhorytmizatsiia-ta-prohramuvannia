# Розділ 15. Складність алгоритмів

## 15.1 Навіщо оцінювати складність

Одну задачу можна розв'язати різними алгоритмами. Вибір між ними
не можна робити «на око»: різниця буває в мільйони разів.

Приклад: пошук у масиві з 1 000 000 елементів.
- лінійний пошук — до 1 000 000 порівнянь;
- двійковий пошук — 20 порівнянь.

Міряти час секундоміром недостатньо: результат залежить від
комп'ютера, мови, компілятора. Потрібна **машинно-незалежна** оцінка —
як зростає кількість операцій при зростанні розміру вхідних даних.

## 15.2 Асимптотичні позначення

Нехай T(n) — кількість елементарних операцій для входу розміру n.

| Позначення | Зміст | Формально |
|------------|-------|-----------|
| **O(f)** | **верхня** межа («не гірше ніж») | T(n) ≤ c·f(n) для n ≥ n₀ |
| **Ω(f)** | нижня межа («не краще ніж») | T(n) ≥ c·f(n) |
| **Θ(f)** | точна оцінка | O(f) і Ω(f) одночасно |

На практиці найчастіше кажуть «складність O(…)», маючи на увазі Θ.

### Правила спрощення
1. **Константи відкидаються:** O(3n) = O(n), O(n/2) = O(n).
2. **Залишається старший член:** O(n² + n + 100) = O(n²).
3. **Послідовні ділянки — сума:** O(n) + O(n²) = O(n²).
4. **Вкладені цикли — добуток:** O(n) · O(m) = O(n·m).
5. Основа логарифма не важлива: O(log₂n) = O(log₁₀n) = O(log n).

## 15.3 Класи складності

| O | Назва | n=10 | n=1 000 | n=10⁶ |
|---|-------|------|---------|-------|
| O(1) | константна | 1 | 1 | 1 |
| O(log n) | логарифмічна | 3 | 10 | 20 |
| O(n) | лінійна | 10 | 10³ | 10⁶ |
| O(n log n) | лінеарифмічна | 33 | 10⁴ | 2·10⁷ |
| O(n²) | квадратична | 100 | 10⁶ | 10¹² |
| O(n³) | кубічна | 10³ | 10⁹ | 10¹⁸ |
| O(2ⁿ) | експоненційна | 1024 | ∞* | ∞* |
| O(n!) | факторіальна | 3.6·10⁶ | ∞* | ∞* |

*\* не дорахується за час існування Всесвіту.*

### Практичне правило
Сучасний комп'ютер виконує ≈10⁸–10⁹ простих операцій за секунду.
Отже, за 1 секунду реально обробити приблизно:

| Складність | Максимальне n |
|------------|---------------|
| O(n!) | 10–11 |
| O(2ⁿ) | 20–25 |
| O(n³) | 300–500 |
| O(n²) | 10 000 |
| O(n log n) | 10⁶ |
| O(n) | 10⁷–10⁸ |
| O(log n) | практично будь-яке |

Таблиця відповідає C++ (≈10⁸–10⁹ операцій за секунду). У Python операцій за секунду зазвичай у 10–100 разів менше, у JavaScript (Node.js) — ближче до C++, але з поправкою на «розігрів» JIT-компілятора.

## 15.4 Як підрахувати складність

### O(1) — не залежить від n

**Python**

```python
x = a[0] + a[-1]
d = n % 10
```

**C++**

```cpp
int x = a[0] + a.back();
int d = n % 10;
```

**JavaScript**

```javascript
const x = a[0] + a.at(-1);
const d = n % 10;
```

### O(n) — один прохід

**Python**

```python
s = 0
for x in a:          # n ітерацій
    s += x           # O(1) кожна
```

**C++**

```cpp
int s = 0;
for (int x : a) {                  // n ітерацій
    s += x;                        // O(1) кожна
}
```

**JavaScript**

```javascript
let s = 0;
for (const x of a) {               // n ітерацій
  s += x;                          // O(1) кожна
}
```

### O(n²) — вкладені цикли по n

**Python**

```python
for i in range(n):
    for j in range(n):
        ...
```

**C++**

```cpp
for (int i = 0; i < n; ++i) {
    for (int j = 0; j < n; ++j) {
        // ...
    }
}
```

**JavaScript**

```javascript
for (let i = 0; i < n; i++) {
  for (let j = 0; j < n; j++) {
    // ...
  }
}
```

Навіть «трикутний» цикл дає O(n²):

**Python**

```python
for i in range(n):
    for j in range(i + 1, n):      # n(n-1)/2 ітерацій = O(n²)
        ...
```

**C++**

```cpp
for (int i = 0; i < n; ++i) {
    for (int j = i + 1; j < n; ++j) {      // n(n-1)/2 ітерацій = O(n²)
        // ...
    }
}
```

**JavaScript**

```javascript
for (let i = 0; i < n; i++) {
  for (let j = i + 1; j < n; j++) {        // n(n-1)/2 ітерацій = O(n²)
    // ...
  }
}
```

### O(log n) — розмір задачі щоразу зменшується в k разів

**Python**

```python
while n > 0:
    n //= 2            # log2(n) ітерацій
```

**C++**

```cpp
while (n > 0) {
    n /= 2;                // log2(n) ітерацій
}
```

**JavaScript**

```javascript
while (n > 0) {
  n = Math.floor(n / 2);   // log2(n) ітерацій
}
```

### O(n log n) — log n рівнів, на кожному O(n) роботи
Сортування злиттям, Timsort.

### O(2ⁿ) — два рекурсивні виклики без мемоізації

**Python**

```python
def fib(n):
    return n if n < 2 else fib(n-1) + fib(n-2)
```

**C++**

```cpp
long long fib(int n) {
    return n < 2 ? n : fib(n - 1) + fib(n - 2);
}
```

**JavaScript**

```javascript
function fib(n) {
  return n < 2 ? n : fib(n - 1) + fib(n - 2);
}
```

## 15.5 Прихована складність вбудованих операцій

Найчастіша помилка студентів — вважати, що `in` чи `insert` безкоштовні.

| Операція | list | dict / set |
|----------|------|------------|
| доступ за індексом/ключем | O(1) | O(1) |
| `x in collection` | **O(n)** | **O(1)** |
| `append` / `add` | O(1) | O(1) |
| `insert(0, x)` | **O(n)** | — |
| `pop()` | O(1) | — |
| `pop(0)` | **O(n)** | — |
| `remove(x)` / `del d[k]` | O(n) | O(1) |
| `min` / `max` / `sum` | O(n) | O(n) |
| `sort()` | O(n log n) | — |
| зріз `a[i:j]` | O(j−i) | — |
| `len` | O(1) | O(1) |

Те саме для структур даних C++ і JavaScript:

| Операція | C++ `vector` | C++ `unordered_set` / `unordered_map` | C++ `set` / `map` | JS `Array` | JS `Set` / `Map` |
|----------|--------------|--------------------------------------|-------------------|------------|-----------------|
| доступ за індексом/ключем | O(1) | O(1) у середньому | O(log n) | O(1) | O(1) |
| пошук елемента (`x in`) | O(n) (`find`) | O(1) у середньому | O(log n) | O(n) (`includes`) | O(1) (`has`) |
| додавання в кінець / вставка | O(1) амортизовано | O(1) у середньому | O(log n) | O(1) (`push`) | O(1) |
| вставка на початок | O(n) | — | — | O(n) (`unshift`) | — |
| видалення елемента | O(n) | O(1) у середньому | O(log n) | O(n) (`splice`) | O(1) |
| сортування | O(n log n) (`sort`) | — | вже впорядковано | O(n log n) (`sort`) | — |

### Класичний приклад оптимізації

**Python**

```python
# O(n·m) — для кожного елемента лінійний пошук
common = [x for x in a if x in b]              # b — список

# O(n+m) — перевірка входження за O(1)
bset = set(b)
common = [x for x in a if x in bset]
```

**C++**

```cpp
// O(n·m) — для кожного елемента лінійний пошук (b — вектор)
vector<int> common;
for (int x : a) {
    if (find(b.begin(), b.end(), x) != b.end()) {
        common.push_back(x);
    }
}

// O(n+m) — перевірка входження за O(1)
unordered_set<int> bset(b.begin(), b.end());
common.clear();
for (int x : a) {
    if (bset.count(x)) {
        common.push_back(x);
    }
}
```

**JavaScript**

```javascript
// O(n·m) — для кожного елемента лінійний пошук (b — масив)
let common = a.filter(x => b.includes(x));

// O(n+m) — перевірка входження за O(1)
const bset = new Set(b);
common = a.filter(x => bset.has(x));
```

### Конкатенація рядків

**Python**

```python
s = ""
for ch in parts:        # O(n²): щоразу новий рядок
    s += ch

s = "".join(parts)      # O(n)
```

**C++**

```cpp
string s;
for (const string &ch : parts) {
    s += ch;                // амортизовано O(1) на додавання: загалом O(n), бо string змінний
}
```

**JavaScript**

```javascript
let s = "";
for (const ch of parts) {
  s += ch;                  // сучасні рушії оптимізують, але для великих обсягів надійніше join
}

const t = parts.join("");   // O(n)
```

Квадратична конкатенація — специфіка мов із незмінними рядками (Python). У C++ вона виникає лише при `s = s + ch` (щоразу нова копія).

## 15.6 Складність рекурсії

Для рекурсії вигляду T(n) = a·T(n/b) + O(nᵏ) — основна теорема
(Master theorem). Прості випадки:

| Рекурентність | Приклад | Складність |
|---------------|---------|------------|
| T(n) = T(n−1) + O(1) | факторіал | O(n) |
| T(n) = T(n−1) + O(n) | сортування вибором | O(n²) |
| T(n) = T(n/2) + O(1) | двійковий пошук | O(log n) |
| T(n) = 2T(n/2) + O(n) | сортування злиттям | O(n log n) |
| T(n) = 2T(n−1) + O(1) | ханойські башні | O(2ⁿ) |

**Пам'ять** рекурсії = глибина стека:
`factorial(n)` — O(n), `merge_sort` — O(log n) стека + O(n) даних.

## 15.7 Складність за пам'яттю

Оцінюється **додаткова** (крім входу) пам'ять.

**Python**

```python
# O(1) додаткової пам'яті
def reverse_inplace(a):
    for i in range(len(a) // 2):
        a[i], a[-1-i] = a[-1-i], a[i]

# O(n) додаткової пам'яті
def reverse_copy(a):
    return a[::-1]
```

**C++**

```cpp
// O(1) додаткової пам'яті
void reverse_inplace(vector<int> &a) {
    for (size_t i = 0; i < a.size() / 2; ++i) {
        swap(a[i], a[a.size() - 1 - i]);
    }
}

// O(n) додаткової пам'яті
vector<int> reversed_copy(const vector<int> &a) {
    return vector<int>(a.rbegin(), a.rend());
}
```

**JavaScript**

```javascript
// O(1) додаткової пам'яті
function reverseInplace(a) {
  for (let i = 0; i < Math.floor(a.length / 2); i++) {
    [a[i], a[a.length - 1 - i]] = [a[a.length - 1 - i], a[i]];
  }
}

// O(n) додаткової пам'яті
function reverseCopy(a) {
  return [...a].reverse();
}
```

Часто існує **компроміс час ↔ пам'ять** (time–space tradeoff):
мемоізація витрачає пам'ять, щоб зекономити час.

## 15.8 Кращий, середній і гірший випадки

| Алгоритм | Кращий | Середній | Гірший |
|----------|--------|----------|--------|
| лінійний пошук | O(1) — перший елемент | O(n) | O(n) — немає |
| двійковий пошук | O(1) — середина | O(log n) | O(log n) |
| вставками | O(n) — відсортовано | O(n²) | O(n²) — зворотно |
| quicksort | O(n log n) | O(n log n) | O(n²) |
| злиттям | O(n log n) | O(n log n) | O(n log n) |

Для надійності зазвичай орієнтуються на **гірший** випадок.

## 15.9 Вимірювання на практиці

**Python**

```python
import time

t0 = time.perf_counter()
algorithm(data)
print(f"{time.perf_counter() - t0:.4f} с")
```

**C++**

```cpp
auto t0 = chrono::steady_clock::now();
algorithm(data);
auto t1 = chrono::steady_clock::now();
cout << fixed << setprecision(4) << chrono::duration<double>(t1 - t0).count() << " с" << endl;
```

**JavaScript**

```javascript
const t0 = performance.now();
algorithm(data);
console.log(`${((performance.now() - t0) / 1000).toFixed(4)} с`);
```

У C++ використовують `<chrono>` (`steady_clock` — для вимірювання інтервалів), у JavaScript — `performance.now()` або `console.time()`/`console.timeEnd()`.

**Python**

```python
import timeit
timeit.timeit("sorted(a)", globals=globals(), number=1000)
```

**C++**

```cpp
auto t0 = chrono::steady_clock::now();
for (int i = 0; i < 1000; ++i) {
    vector<int> b = a;
    sort(b.begin(), b.end());
}
double total = chrono::duration<double>(chrono::steady_clock::now() - t0).count();   // секунди на 1000 повторів
```

**JavaScript**

```javascript
console.time("sorted");
for (let i = 0; i < 1000; i++) {
  [...a].sort((x, y) => x - y);
}
console.timeEnd("sorted");                // виводить час на 1000 повторів
```

Готового `timeit` у C++ і JavaScript немає. У C++ з оптимізаціями (`-O2`) компілятор може викинути «марну» роботу, результат якої не використовується; у JavaScript перші повторення повільніші через «розігрів» JIT — тому вимірюють багато повторів і відкидають перші.

### Експериментальна перевірка класу складності
Подвоюємо n і дивимось, як змінюється час:

| Якщо час… | Складність |
|-----------|------------|
| не змінився | O(1) або O(log n) |
| зріс у 2 рази | O(n) |
| зріс у ~2.2 рази | O(n log n) |
| зріс у 4 рази | O(n²) |
| зріс у 8 разів | O(n³) |

## 15.10 Чого асимптотика НЕ говорить

- **Константи мають значення** на малих n: O(n²) з малою константою
  може бути швидшим за O(n log n) при n < 50
  (саме тому Timsort усередині використовує сортування вставками).
- Не враховує кеш процесора, локальність даних, вартість пам'яті.
- O(n) з важкою операцією всередині може бути гіршим за O(n log n)
  з дешевою.

**Висновок:** асимптотика — інструмент вибору алгоритму,
а остаточне рішення підтверджується вимірюванням на реальних даних.

**Три мови — різні константи.** Той самий алгоритм O(n) у C++ зазвичай виконується в десятки разів швидше, ніж у Python, бо C++ компілюється в машинний код, а Python інтерпретується; JavaScript (JIT-компіляція в Node.js) зазвичай посередині. Проте клас складності від мови не залежить: алгоритм O(n²) у C++ при великому n все одно програє алгоритму O(n log n) у Python.
