# Chapter 11. Sorting and Searching

## 11.1 The Sorting Problem

**Given:** a sequence a[0..n−1].
**Find:** a permutation of the elements in which a[0] ≤ a[1] ≤ … ≤ a[n−1].

### Characteristics of Sorting Algorithms

- **Time complexity** (best / average / worst case).
- **Memory**: *in place* (in-place, O(1) extra) or not.
- **Stability** (stable): equal elements keep their relative order.
  This matters when sorting by several keys.
- **Number of comparisons and swaps**.

## 11.2 Simple Sorts — O(n²)

### Selection sort
At each step we find the minimum in the "unsorted" part
and put it in its place.

**Python**

```python
def selection_sort(a):
    n = len(a)
    for i in range(n - 1):
        mi = i
        for j in range(i + 1, n):
            if a[j] < a[mi]:
                mi = j
        a[i], a[mi] = a[mi], a[i]
    return a
```

**C++**

```cpp
// sorts in place
    int n = a.size();
    for (int i = 0; i < n - 1; ++i) {
        int mi = i;
        for (int j = i + 1; j < n; ++j) {
            if (a[j] < a[mi]) {
                mi = j;
            }
        }
        swap(a[i], a[mi]);
    }
}
```

**JavaScript**

```javascript
function selectionSort(a) {
  const n = a.length;
  for (let i = 0; i < n - 1; i++) {
    let mi = i;
    for (let j = i + 1; j < n; j++) {
      if (a[j] < a[mi]) {
        mi = j;
      }
    }
    [a[i], a[mi]] = [a[mi], a[i]];
  }
  return a;
}
```

In C++ the vector is passed by reference `&` and sorted in place, so `return a` is not needed.

Always n(n−1)/2 comparisons, ≤ n−1 swaps. **Not stable.**

### Insertion sort
We take an element and "insert" it in the right place among the previous ones.

**Python**

```python
def insertion_sort(a):
    for i in range(1, len(a)):
        key = a[i]
        j = i - 1
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key
    return a
```

**C++**

```cpp
void insertion_sort(vector<int> &a) {
    for (size_t i = 1; i < a.size(); ++i) {
        int key = a[i];
        int j = (int)i - 1;
        while (j >= 0 && a[j] > key) {
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = key;
    }
}
```

**JavaScript**

```javascript
function insertionSort(a) {
  for (let i = 1; i < a.length; i++) {
    const key = a[i];
    let j = i - 1;
    while (j >= 0 && a[j] > key) {
      a[j + 1] = a[j];
      j--;
    }
    a[j + 1] = key;
  }
  return a;
}
```

On **almost sorted** data — O(n). **Stable.**
The best choice for small arrays (n < 20).

### Exchange sort ("bubble sort")
Adjacent elements are compared and swapped if necessary.

**Python**

```python
def bubble_sort(a):
    n = len(a)
    for i in range(n - 1):
        swapped = False
        for j in range(n - 1 - i):
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                swapped = True
        if not swapped:          # already sorted — exit
            break
    return a
```

**C++**

```cpp
void bubble_sort(vector<int> &a) {
    int n = a.size();
    for (int i = 0; i < n - 1; ++i) {
        bool swapped = false;
        for (int j = 0; j < n - 1 - i; ++j) {
            if (a[j] > a[j + 1]) {
                swap(a[j], a[j + 1]);
                swapped = true;
            }
        }
        // already sorted — exit
            break;
        }
    }
}
```

**JavaScript**

```javascript
function bubbleSort(a) {
  const n = a.length;
  for (let i = 0; i < n - 1; i++) {
    let swapped = false;
    for (let j = 0; j < n - 1 - i; j++) {
      if (a[j] > a[j + 1]) {
        [a[j], a[j + 1]] = [a[j + 1], a[j]];
        swapped = true;
      }
    }
    // already sorted — exit
      break;
    }
  }
  return a;
}
```

**Stable.** The slowest of the three in practice, but the simplest.

## 11.3 Fast Sorts — O(n log n)

### Merge sort
Divide and conquer: split in half, sort each half,
merge.

**Python**

```python
def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left = merge_sort(a[:mid])
    right = merge_sort(a[mid:])
    return merge(left, right)


def merge(x, y):
    res, i, j = [], 0, 0
    while i < len(x) and j < len(y):
        if x[i] <= y[j]:
            res.append(x[i]); i += 1
        else:
            res.append(y[j]); j += 1
    res += x[i:] + y[j:]
    return res
```

**C++**

```cpp
// the name merge is already taken in std in C++
    vector<int> res;
    size_t i = 0, j = 0;
    while (i < x.size() && j < y.size()) {
        if (x[i] <= y[j]) {
            res.push_back(x[i++]);
        } else {
            res.push_back(y[j++]);
        }
    }
    res.insert(res.end(), x.begin() + i, x.end());
    res.insert(res.end(), y.begin() + j, y.end());
    return res;
}

vector<int> merge_sort(const vector<int> &a) {
    if (a.size() <= 1) {
        return a;
    }
    size_t mid = a.size() / 2;
    vector<int> left = merge_sort(vector<int>(a.begin(), a.begin() + mid));
    vector<int> right = merge_sort(vector<int>(a.begin() + mid, a.end()));
    return merge_vectors(left, right);
}
```

**JavaScript**

```javascript
function mergeSort(a) {
  if (a.length <= 1) {
    return a;
  }
  const mid = Math.floor(a.length / 2);
  const left = mergeSort(a.slice(0, mid));
  const right = mergeSort(a.slice(mid));
  return merge(left, right);
}

function merge(x, y) {
  const res = [];
  let i = 0, j = 0;
  while (i < x.length && j < y.length) {
    if (x[i] <= y[j]) {
      res.push(x[i++]);
    } else {
      res.push(y[j++]);
    }
  }
  return res.concat(x.slice(i), y.slice(j));
}
```

C++ has a ready-made `merge` algorithm (`<algorithm>`) for merging two sorted ranges, as well as `inplace_merge`.

Always O(n log n). **Stable**, but needs O(n) memory.

### Quicksort
We choose a pivot element and split into "smaller" and "larger".

**Python**

```python
def quick_sort(a):
    if len(a) <= 1:
        return a
    pivot = a[len(a) // 2]
    less = [x for x in a if x < pivot]
    equal = [x for x in a if x == pivot]
    greater = [x for x in a if x > pivot]
    return quick_sort(less) + equal + quick_sort(greater)
```

**C++**

```cpp
vector<int> quick_sort(const vector<int> &a) {
    if (a.size() <= 1) {
        return a;
    }
    int pivot = a[a.size() / 2];
    vector<int> less, equal, greater;
    for (int x : a) {
        if (x < pivot) less.push_back(x);
        else if (x == pivot) equal.push_back(x);
        else greater.push_back(x);
    }
    vector<int> res = quick_sort(less);
    res.insert(res.end(), equal.begin(), equal.end());
    vector<int> right = quick_sort(greater);
    res.insert(res.end(), right.begin(), right.end());
    return res;
}
```

**JavaScript**

```javascript
function quickSort(a) {
  if (a.length <= 1) {
    return a;
  }
  const pivot = a[Math.floor(a.length / 2)];
  const less = a.filter(x => x < pivot);
  const equal = a.filter(x => x === pivot);
  const greater = a.filter(x => x > pivot);
  return [...quickSort(less), ...equal, ...quickSort(greater)];
}
```

This is a teaching version with O(n) extra memory. In real code quicksort is done "in place", swapping elements around the pivot (Lomuto or Hoare schemes).

Average case O(n log n), worst case O(n²) (an unlucky pivot).
In practice the fastest of the comparison sorts.

## 11.4 Comparison Table

| Algorithm | Best | Average | Worst | Memory | Stable |
|-----------|------|---------|-------|--------|--------|
| selection | O(n²) | O(n²) | O(n²) | O(1) | no |
| insertion | O(n) | O(n²) | O(n²) | O(1) | yes |
| bubble | O(n) | O(n²) | O(n²) | O(1) | yes |
| merge | O(n log n) | O(n log n) | O(n log n) | O(n) | yes |
| quick | O(n log n) | O(n log n) | O(n²) | O(log n) | no |
| `sorted()` (Timsort) | O(n) | O(n log n) | O(n log n) | O(n) | yes |

**The theoretical bound** for comparison-based sorts: Ω(n log n).

## 11.5 Python's Built-In Sorting

**Python**

```python
a.sort()                              # in place, returns None
b = sorted(a)                         # a new list
sorted(a, reverse=True)               # descending
sorted(words, key=len)                # by length
sorted(people, key=lambda p: p[1])    # by the second element
sorted(data, key=lambda p: (-p[1], p[0]))   # by two keys
```

**C++**

```cpp
// in place
vector<int> b = a;
// "sorted(a)": a copy + sort
// descending

// by length
     [](const string &x, const string &y) { return x.size() < y.size(); });

// by the second element
     [](const auto &p, const auto &q) { return p.second < q.second; });

// by two keys
     [](const auto &p, const auto &q) {
         return p.second != q.second ? p.second > q.second : p.first < q.first;
     });
```

**JavaScript**

```javascript
// in place (for numbers — with a comparator!)
// "sorted(a)": a new array
// descending

// by length
// by the second element
// by two keys
```

The algorithm is **Timsort** (a merge + insertion hybrid), stable,
and it exploits already ordered runs.

In C++ `std::sort` is *introsort* (a hybrid of quicksort, heapsort and insertion sort): O(n log n) even in the worst case, but **not stable**; the stable variant is `std::stable_sort`. In JavaScript `Array.prototype.sort` has been **stable** since 2019 (ES2019); in the V8 engine it is also Timsort.

## 11.6 Linear Search — O(n)

**Python**

```python
def linear_search(a, target):
    for i, x in enumerate(a):
        if x == target:
            return i
    return -1
```

**C++**

```cpp
int linear_search(const vector<int> &a, int target) {
    for (size_t i = 0; i < a.size(); ++i) {
        if (a[i] == target) {
            return i;
        }
    }
    return -1;
}
```

**JavaScript**

```javascript
function linearSearch(a, target) {
  for (let i = 0; i < a.length; i++) {
    if (a[i] === target) {
      return i;
    }
  }
  return -1;
}
```

Ready-made tools: `find(a.begin(), a.end(), target)` in C++, `a.indexOf(target)` in JavaScript.

Works on **any** array. For a sorted one, with early
termination: if `x > target`, there is no point searching further.

## 11.7 Binary Search — O(log n)

Works **only on a sorted** array.

**Python**

```python
def binary_search(a, target):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

**C++**

```cpp
// the name binary_search is taken in std
    int lo = 0, hi = (int)a.size() - 1;
    while (lo <= hi) {
        // safe from overflow
        if (a[mid] == target) {
            return mid;
        }
        if (a[mid] < target) {
            lo = mid + 1;
        } else {
            hi = mid - 1;
        }
    }
    return -1;
}
```

**JavaScript**

```javascript
function binarySearch(a, target) {
  let lo = 0, hi = a.length - 1;
  while (lo <= hi) {
    const mid = Math.floor((lo + hi) / 2);
    if (a[mid] === target) {
      return mid;
    }
    if (a[mid] < target) {
      lo = mid + 1;
    } else {
      hi = mid - 1;
    }
  }
  return -1;
}
```

In C++ the expression `(lo + hi) / 2` can overflow `int` for very large arrays, so `lo + (hi - lo) / 2` is written. In Python and JavaScript (for numbers up to 2⁵³) this problem does not exist.

The recursive version:

**Python**

```python
def bsearch_rec(a, target, lo=0, hi=None):
    if hi is None:
        hi = len(a) - 1
    if lo > hi:
        return -1
    mid = (lo + hi) // 2
    if a[mid] == target:
        return mid
    if a[mid] < target:
        return bsearch_rec(a, target, mid + 1, hi)
    return bsearch_rec(a, target, lo, mid - 1)
```

**C++**

```cpp
int bsearch_rec(const vector<int> &a, int target, int lo, int hi) {
    if (lo > hi) {
        return -1;
    }
    int mid = lo + (hi - lo) / 2;
    if (a[mid] == target) {
        return mid;
    }
    if (a[mid] < target) {
        return bsearch_rec(a, target, mid + 1, hi);
    }
    return bsearch_rec(a, target, lo, mid - 1);
}

// the overload replaces hi=None
    return bsearch_rec(a, target, 0, (int)a.size() - 1);
}
```

**JavaScript**

```javascript
// default values may depend on earlier parameters
  if (lo > hi) {
    return -1;
  }
  const mid = Math.floor((lo + hi) / 2);
  if (a[mid] === target) {
    return mid;
  }
  if (a[mid] < target) {
    return bsearchRec(a, target, mid + 1, hi);
  }
  return bsearchRec(a, target, lo, mid - 1);
}
```

### Why O(log n)
Each step **halves** the search range:
n → n/2 → n/4 → … → 1, that is, log₂n steps.

| n | linear (worst) | binary |
|---|----------------|--------|
| 100 | 100 | 7 |
| 1 000 | 1 000 | 10 |
| 1 000 000 | 1 000 000 | 20 |
| 10⁹ | 10⁹ | 30 |

## 11.8 What to Use When

| Situation | Solution |
|-----------|----------|
| a single search in an unsorted array | linear search |
| many searches in a static array | sort + binary search |
| only a membership check is needed | `set` — O(1) |
| lookup by key | `dict` — O(1) |
| a real-world working task | `sorted()` / `in` |

Counterparts: C++ — `sort`, `binary_search`, `unordered_set`, `unordered_map`; JavaScript — `sort`, `includes`, `Set`, `Map`.

**Important:** sorting costs O(n log n). If there is just one search,
linear search is cheaper than "sort and then binary search".
