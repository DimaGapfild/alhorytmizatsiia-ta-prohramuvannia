# Chapter 2. Flowcharts and Pseudocode

## 2.1 Purpose of a Flowchart

A **flowchart** is a graphical representation of an algorithm in which each action
is shown by a geometric shape and the order of execution by arrows (flow lines).

Advantages: clarity, independence from any programming language.
Disadvantages: bulky for large algorithms.

Standard: ISO 5807 (the Ukrainian DSTU ISO 5807; analogous to GOST 19.701-90).

## 2.2 Basic Blocks

| Shape | Name | Purpose |
|-------|------|---------|
| oval | **Terminator** | start / end of the algorithm |
| parallelogram | **Data** | input / output |
| rectangle | **Process** | computation, assignment |
| diamond | **Decision** | condition check (2 exits: yes/no) |
| hexagon | **Preparation** | header of a `for` loop |
| rectangle with double side borders | **Predefined process** | call to a subroutine |
| circle | **Connector** | break in a flow line |

### Drawing Rules
1. A "Process" block has one entrance and one exit.
2. Flow goes top to bottom, left to right; arrowheads are required only where the flow deviates from this.
3. Exactly two lines leave a diamond, labeled **yes** / **no**.
4. Blocks are numbered so they can be referenced in the text.
5. Lines do not cross (use connectors instead).

## 2.3 The Three Basic Structures in Flowcharts

```
SEQUENCE          BRANCHING                 "WHILE" LOOP
                                        
 ┌─────────┐          ◇ condition        ┌──►◇ condition ──no──►
 │ action 1│        yes│   │no           │    │yes
 └────┬────┘      ┌────┘   └────┐        │  ┌─▼──────┐
 ┌────▼────┐   ┌──▼───┐   ┌──▼───┐       └──┤ body   │
 │ action 2│   │ act. A│  │ act. B│         └────────┘
 └─────────┘   └──┬───┘   └──┬───┘
                  └────┬─────┘
                       ▼
```

## 2.4 Example: Maximum of Two Numbers

```
       │  Start   │
       └─────┬────┘
       ╔═════▼═════╗
       ║ Input a,b ║
       ╚═════┬═════╝
             │
          ◇ a > b ?
      yes │     │ no

```

## 2.5 Pseudocode

**Pseudocode** is a text notation for an algorithm that uses keywords
but does not follow the strict syntax of any particular language.

### Conventions Used in This Course

| Construct | Notation |
|-----------|----------|
| start/end | `BEGIN` … `END` |
| input/output | `INPUT x`, `OUTPUT x` |
| assignment | `x ← expression` |
| branching | `IF condition THEN … ELSE … END` |
| loop with a precondition | `WHILE condition DO … END` |
| loop with a counter | `FOR i FROM 1 TO n DO … END` |
| loop with a postcondition | `REPEAT … UNTIL condition` |
| subroutine | `FUNCTION f(x) … RETURN y … END` |
| comment | `// text` |

### Example: the Sum of Numbers from 1 to n

```
BEGIN
  INPUT n
  s ← 0
  FOR i FROM 1 TO n DO
    s ← s + i
  END
  OUTPUT s
END
```

### The Same Algorithm in Python

```python
n = int(input())
s = 0
for i in range(1, n + 1):
    s += i
print(s)
```

## 2.6 Tracing an Algorithm

**Tracing** is filling in a table of variable values step by step.
It is the main way to check an algorithm "on paper".

Example for n = 4:

| Step | i | s | Condition i ≤ n |
|------|---|---|-----------------|
| 0 | — | 0 | — |
| 1 | 1 | 1 | yes |
| 2 | 2 | 3 | yes |
| 3 | 3 | 6 | yes |
| 4 | 4 | 10 | yes |
| 5 | 5 | 10 | no → exit |

Result: s = 10. ✔
