# Chapter 1. Introduction to Algorithmization

## 1.1 The Concept of an Algorithm

An **algorithm** is a well-defined finite sequence of actions that transforms
input data into a result in a finite amount of time.

The word comes from the name of the 9th-century mathematician al-Khwārizmī.

## 1.2 Properties of an Algorithm

| Property | Meaning | Example of violation |
|----------|---------|----------------------|
| **Discreteness** | consists of separate, completed steps | "mix it up somehow" |
| **Definiteness** (determinism) | every step is unambiguous and leaves no room for interpretation | "add a little salt" |
| **Effectiveness** | terminates and produces a result | an infinite loop |
| **Generality** | works for a whole class of inputs | "solve 2x=6" (only one case) |
| **Finiteness** | the number of steps is bounded | "go through all natural numbers" |
| **Correctness** | the result matches the problem | a sort that corrupts the data |

## 1.3 The Executor of an Algorithm

An **executor** is an object that carries out the commands of an algorithm.
It is characterized by:
- **command system** — the set of actions it understands;
- **environment** — the conditions in which it operates;
- **failures** — situations in which a command cannot be executed.

Example: the executor is a "processor", its command system is machine
instructions, and a failure is division by zero.

## 1.4 Ways to Describe Algorithms

1. **Verbal** — text in natural language.
2. **Graphical** — a flowchart (see Chapter 2).
3. **Pseudocode** — a semi-formal language between natural language and a programming language.
4. **Tabular** — transition tables, decision tables.
5. **Program** — a listing in a programming language.

### Example: a verbal description

Problem: find the sum of two numbers.

```
1. Get the number a.
2. Get the number b.
3. Compute s = a + b.
4. Output s.
5. End.
```

## 1.5 Basic Algorithm Structures

Any algorithm can be built from three constructs
(the Böhm–Jacopini theorem):

| Structure | Name | Essence |
|-----------|------|---------|
| **Sequence** | linear | actions one after another |
| **Branching** | conditional | choosing one of several branches by a condition |
| **Repetition** | iterative | repeating actions |

## 1.6 Stages of Solving a Problem on a Computer

1. **Problem statement** — what is given, what must be found.
2. **Building a mathematical model** — formulas, constraints.
3. **Designing the algorithm** — flowchart / pseudocode.
4. **Writing the program** — coding.
5. **Testing and debugging** — checking against tests, including edge cases.
6. **Analysis of results and documentation**.

## 1.7 Input, Output, and Intermediate Data

- **Input** — what the algorithm receives (`a`, `b`).
- **Output** — the result (`s`).
- **Intermediate** — auxiliary values needed only during the computation.

## 1.8 An Example of a Fully Written-Up Problem

**Problem.** Compute the area of a right triangle from its legs.

- **Given:** a > 0, b > 0 — the lengths of the legs.
- **Find:** S — the area.
- **Model:** S = (a · b) / 2.
- **Algorithm:**
  ```
  BEGIN
    INPUT a, b
    S ← a * b / 2
    OUTPUT S
  END
  ```
- **Tests:** (3, 4) → 6; (1, 1) → 0.5; (10, 0.2) → 1.0.
