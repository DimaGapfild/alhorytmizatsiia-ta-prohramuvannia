# Chapter 14. Fundamentals of Object-Oriented Programming

## 14.1 From Procedural to Object-Oriented

The procedural approach: **data on one side, functions on the other**.

**Python**

```python
student = {"name": "Koval", "grades": [74, 82]}

def average(s):
    return sum(s["grades"]) / len(s["grades"])
```

**C++**

```cpp
// the fields of a struct are checked by the compiler
    string name;
    vector<int> grades;
};

// a function separate from the data
    return accumulate(s.grades.begin(), s.grades.end(), 0.0) / s.grades.size();
}

Student student = {"Koval", {74, 82}};
```

**JavaScript**

```javascript
const student = { name: "Koval", grades: [74, 82] };

function average(s) {
  return s.grades.reduce((p, q) => p + q, 0) / s.grades.length;
}
```

In C++ a missing field in a `struct` is a compilation error; in Python and JavaScript a missing key shows up only at run time.

The problem: nothing guarantees that the dictionary has the required keys,
and the function `average` is in no way "tied" to the data.

OOP **combines data and behavior** in a single entity — an object.

## 14.2 Class and Object

- A **class** is a description (a template, a type) of an entity: what data and actions it has.
- An **object (instance)** is a concrete embodiment of a class.

An analogy: the class is the "blueprint of a car", the object is a specific car.

**Python**

```python
class Student:
    """A student with a set of grades."""

    def __init__(self, name: str, group: str):
        self.name = name            # an instance attribute
        self.group = group
        self.grades: list[int] = []

    def add_grade(self, score: int) -> None:
        """Adds a grade, checking the range."""
        if not 0 <= score <= 100:
            raise ValueError(f"score {score} is outside 0..100")
        self.grades.append(score)

    def average(self) -> float:
        """The average score; 0 if there are no grades."""
        return sum(self.grades) / len(self.grades) if self.grades else 0.0


s = Student("Koval", "CS-21")       # creating an object
s.add_grade(74)
s.add_grade(82)
print(s.average())                  # 78.0
```

**C++**

```cpp
// A student with a set of grades.
class Student {
public:
    // the constructor
        : name(move(name)), group(move(group)) {}

    // Adds a grade, checking the range.
        if (!(0 <= score && score <= 100)) {
            throw invalid_argument("score " + to_string(score) + " is outside 0..100");
        }
        grades.push_back(score);
    }

    // The average score; 0 if there are no grades.
        if (grades.empty()) return 0.0;
        return accumulate(grades.begin(), grades.end(), 0.0) / grades.size();
    }

    // instance attributes (fields)
    string group;
    vector<int> grades;
};

int main() {
    Student s("Koval", "CS-21");             // creating an object
    s.add_grade(74);
    s.add_grade(82);
    cout << s.average() << endl;              // 78
}
```

**JavaScript**

```javascript
// A student with a set of grades.
class Student {
  // the constructor
    // an instance property
    this.group = group;
    this.grades = [];
  }

  // Adds a grade, checking the range.
    if (!(0 <= score && score <= 100)) {
      throw new RangeError(`score ${score} is outside 0..100`);
    }
    this.grades.push(score);
  }

  // The average score; 0 if there are no grades.
    if (this.grades.length === 0) return 0;
    return this.grades.reduce((p, q) => p + q, 0) / this.grades.length;
  }
}

const s = new Student("Koval", "CS-21");     // creating an object: the word new
s.addGrade(74);
s.addGrade(82);
console.log(s.average());                     // 78
```

In C++ the fields of a class must be **declared** in the class body (with types), and `public`/`private` set the access. In JavaScript creating an object requires the word `new`, and properties appear on assignment `this.x = ...`.

## 14.3 self, __init__, and Attributes

- `__init__` is the **constructor**: it is called automatically on creation.
- `self` is a reference to the **current object**; the first parameter
  of every instance method. It is written in the declaration but not in the call.

**Python**

```python
s.add_grade(74)        # Python passes: Student.add_grade(s, 74)
```

**C++**

```cpp
// C++ implicitly passes the pointer this: add_grade(&s, 74)
```

**JavaScript**

```javascript
// inside the method this refers to s
```

In C++ `this` is a **pointer** to the current object (`this->name`, and often just `name`); it is not written in the parameter list. In JavaScript `this` is determined at call time, so by detaching the method (`const f = s.addGrade; f(74)`) it is easy to lose it.

### Class attributes vs instance attributes

**Python**

```python
class Student:
    university = "NU LP"        # A CLASS ATTRIBUTE — shared by all
    count = 0

    def __init__(self, name):
        self.name = name        # AN INSTANCE ATTRIBUTE — separate for each
        Student.count += 1
```

**C++**

```cpp
class Student {
public:
    inline static const string university = "NU LP";   // A CLASS ATTRIBUTE (static) — shared by all
    inline static int count = 0;

    Student(string name) : name(move(name)) {
        count++;
    }

    // AN INSTANCE ATTRIBUTE — separate for each
};
```

**JavaScript**

```javascript
class Student {
  static university = "NU LP";   // A STATIC FIELD — shared by all
  static count = 0;

  constructor(name) {
    // AN INSTANCE PROPERTY — separate for each
    Student.count += 1;
  }
}
```

## 14.4 Magic (dunder) Methods

| Method | Called by | Purpose |
|--------|-----------|---------|
| `__init__` | `Student(...)` | constructor |
| `__str__` | `print(obj)`, `str(obj)` | user-facing representation |
| `__repr__` | in the REPL, `repr(obj)` | developer-facing representation |
| `__len__` | `len(obj)` | length |
| `__eq__` | `a == b` | equality comparison |
| `__lt__` | `a < b`, `sorted()` | "less than" |
| `__add__` | `a + b` | addition |
| `__getitem__` | `obj[i]` | indexing |
| `__contains__` | `x in obj` | membership |
| `__call__` | `obj()` | calling like a function |

Counterparts in C++ and JavaScript:

| Python | C++ | JavaScript |
|--------|-----|------------|
| `__init__` | constructor `Student(...)` | `constructor` |
| `__str__` | `operator<<` (for `cout`) | `toString()` |
| `__repr__` | your own function | `util.inspect`, `console.log` |
| `__len__` | the `size()` method | the `length` property |
| `__eq__` | `operator==` | none: an `equals` method |
| `__lt__` | `operator<` | none: a comparator function |
| `__add__` | `operator+` | none: an `add` method |
| `__getitem__` | `operator[]` | none: a `get` method |
| `__call__` | `operator()` (a functor) | a function is already a callable object |

In C++ almost any operator can be overloaded; JavaScript has **no** operator overloading.

**Python**

```python
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __str__(self):
        return f"({self.x}; {self.y})"

    def __repr__(self):
        return f"Point({self.x}, {self.y})"

    def __eq__(self, other):
        return (self.x, self.y) == (other.x, other.y)

    def __add__(self, other):
        return Point(self.x + other.x, self.y + other.y)

    def __abs__(self):
        return (self.x ** 2 + self.y ** 2) ** 0.5


p = Point(1, 2) + Point(3, 4)
print(p)              # (4; 6)
print(abs(p))         # 7.211...
```

**C++**

```cpp
class Point {
public:
    Point(double x, double y) : x(x), y(y) {}

    bool operator==(const Point &o) const { return x == o.x && y == o.y; }       // __eq__
    Point operator+(const Point &o) const { return Point(x + o.x, y + o.y); }    // __add__
    // __abs__ (an ordinary method)

    // __str__: output through cout
        return os << "(" << p.x << "; " << p.y << ")";
    }

    double x, y;
};

int main() {
    Point p = Point(1, 2) + Point(3, 4);
    cout << p << endl;                  // (4; 6)
    cout << p.abs() << endl;            // 7.2111
}
```

**JavaScript**

```javascript
class Point {
  constructor(x, y) {
    this.x = x;
    this.y = y;
  }

  toString() { return `(${this.x}; ${this.y})`; }            // __str__
  // __eq__: the == operator cannot be overloaded
  // __add__: the + operator cannot be overloaded
  abs() { return Math.hypot(this.x, this.y); }
}

const p = new Point(1, 2).add(new Point(3, 4));
console.log(String(p));                 // (4; 6)
console.log(p.abs());                   // 7.211102550927978
```

## 14.5 The Three Principles of OOP

### Encapsulation
Hiding the internal structure; access only through methods.

Python conventions (the language does not technically forbid access):

**Python**

```python
self.name       # public
self._cache     # "protected" — do not touch from outside (convention)
self.__secret   # name mangling → _ClassName__secret
```

**C++**

```cpp
class A {
public:
    // public: available to everyone
protected:
    // protected: the class and its descendants — a REAL restriction
private:
    // private: only the methods of this class — a REAL restriction
};
```

**JavaScript**

```javascript
class A {
  // a PRIVATE field (#): a real ban on access from outside

  constructor() {
    // public
    // "protected" — only a convention, as in Python
  }
}
```

Unlike Python, in C++ `private`/`protected` are checked by the compiler. In modern JavaScript fields with `#` give real privacy; an underscore is only a convention.

Properties (`property`) — access like an attribute, with validation:

**Python**

```python
class Temperature:
    def __init__(self, celsius=0):
        self._celsius = celsius

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        if value < -273.15:
            raise ValueError("below absolute zero")
        self._celsius = value

    @property
    def fahrenheit(self):             # computed, read-only
        return self._celsius * 9 / 5 + 32


t = Temperature()
t.celsius = 100          # the setter is called
print(t.fahrenheit)      # 212.0
```

**C++**

```cpp
class Temperature {
public:
    Temperature(double celsius = 0) : celsius_(celsius) {}

    double celsius() const { return celsius_; }                   // getter
    void set_celsius(double value) {                              // setter
        if (value < -273.15) {
            throw invalid_argument("below absolute zero");
        }
        celsius_ = value;
    }

    // computed, read-only

private:
    double celsius_;
};

int main() {
    Temperature t;
    // the setter is called explicitly
    cout << t.fahrenheit() << endl;      // 212
}
```

**JavaScript**

```javascript
class Temperature {
  #celsius;

  constructor(celsius = 0) {
    this.#celsius = celsius;
  }

  get celsius() { return this.#celsius; }
  set celsius(value) {
    if (value < -273.15) {
      throw new RangeError("below absolute zero");
    }
    this.#celsius = value;
  }

  // computed, read-only
}

const t = new Temperature();
// the setter is called
console.log(t.fahrenheit);               // 212
```

C++ has no properties (`property`) — a pair of `get`/`set` methods is used. JavaScript, like Python, has `get`/`set` syntax that looks like ordinary field access.

### Inheritance
A new class receives the data and behavior of the parent.

**Python**

```python
class Person:
    def __init__(self, name):
        self.name = name

    def info(self) -> str:
        return f"Person: {self.name}"


class Student(Person):
    def __init__(self, name, group):
        super().__init__(name)        # calling the parent's constructor
        self.group = group

    def info(self) -> str:            # OVERRIDING
        return f"Student: {self.name}, group {self.group}"


class Teacher(Person):
    def __init__(self, name, subject):
        super().__init__(name)
        self.subject = subject

    def info(self) -> str:
        return f"Teacher: {self.name}, subject {self.subject}"
```

**C++**

```cpp
class Person {
public:
    Person(string name) : name(move(name)) {}
    virtual ~Person() = default;
    virtual string info() const { return "Person: " + name; }          // virtual allows overriding

protected:
    string name;
};

class Student : public Person {
public:
    Student(string name, string group)
        // calling the parent's constructor

    // OVERRIDING
        return "Student: " + name + ", group " + group;
    }

private:
    string group;
};

class Teacher : public Person {
public:
    Teacher(string name, string subject)
        : Person(move(name)), subject(move(subject)) {}

    string info() const override {
        return "Teacher: " + name + ", subject " + subject;
    }

private:
    string subject;
};
```

**JavaScript**

```javascript
class Person {
  constructor(name) {
    this.name = name;
  }

  info() {
    return `Person: ${this.name}`;
  }
}

class Student extends Person {
  constructor(name, group) {
    // calling the parent's constructor
    this.group = group;
  }

  // OVERRIDING
    return `Student: ${this.name}, group ${this.group}`;
  }
}

class Teacher extends Person {
  constructor(name, subject) {
    super(name);
    this.subject = subject;
  }

  info() {
    return `Teacher: ${this.name}, subject ${this.subject}`;
  }
}
```

In C++ dynamic method selection works only for `virtual` functions; `override` asks the compiler to check that the method really overrides a virtual one. The base class should have a `virtual` destructor. In JavaScript all methods are "virtual" by default. Type checks: `dynamic_cast` in C++, `obj instanceof Person` in JavaScript.

Checks: `isinstance(obj, Person)`, `issubclass(Student, Person)`.

### Polymorphism
One interface — different implementations. The code works with the parent type,
and the method of the specific class is called.

**Python**

```python
people = [Student("Koval", "CS-21"), Teacher("Shevchenko", "algorithms")]
for p in people:
    print(p.info())        # each one's "own" info is called
```

**C++**

```cpp
vector<unique_ptr<Person>> people;
people.push_back(make_unique<Student>("Koval", "CS-21"));
people.push_back(make_unique<Teacher>("Shevchenko", "algorithms"));
for (const auto &p : people) {
    // each one's "own" info is called
}
```

**JavaScript**

```javascript
const people = [new Student("Koval", "CS-21"), new Teacher("Shevchenko", "algorithms")];
for (const p of people) {
  // each one's "own" info is called
}
```

In C++ polymorphism works through **pointers or references** to the base class (here — `unique_ptr` smart pointers). If a derived object is assigned to a variable of type `Person` by value, it is "sliced" down to `Person` (slicing).

## 14.6 Abstract Classes

**Python**

```python
from abc import ABC, abstractmethod


class Shape(ABC):
    @abstractmethod
    def area(self) -> float:
        """The area of the shape."""

    @abstractmethod
    def perimeter(self) -> float:
        """The perimeter of the shape."""

    def describe(self) -> str:         # an ordinary shared method
        return f"{type(self).__name__}: S={self.area():.2f}"


class Rectangle(Shape):
    def __init__(self, a, b):
        self.a, self.b = a, b

    def area(self):
        return self.a * self.b

    def perimeter(self):
        return 2 * (self.a + self.b)


Shape()        # TypeError — an abstract class cannot be instantiated
```

**C++**

```cpp
class Shape {
public:
    virtual ~Shape() = default;
    // = 0 — a pure virtual (abstract) method. The area of the shape.
    // The perimeter of the shape.

    // an ordinary shared method
        ostringstream os;
        os << "S=" << fixed << setprecision(2) << area();
        return os.str();
    }
};

class Rectangle : public Shape {
public:
    Rectangle(double a, double b) : a(a), b(b) {}

    double area() const override { return a * b; }
    double perimeter() const override { return 2 * (a + b); }

private:
    double a, b;
};

// Shape s;   // compilation error: an abstract class cannot be instantiated
```

**JavaScript**

```javascript
class Shape {
  constructor() {
    if (new.target === Shape) {
      throw new TypeError("an abstract class cannot be instantiated");
    }
  }

  area() { throw new Error("not implemented"); }
  perimeter() { throw new Error("not implemented"); }

  // an ordinary shared method
    return `${this.constructor.name}: S=${this.area().toFixed(2)}`;
  }
}

class Rectangle extends Shape {
  constructor(a, b) {
    super();
    this.a = a;
    this.b = b;
  }

  area() { return this.a * this.b; }
  perimeter() { return 2 * (this.a + this.b); }
}

// new Shape();   // TypeError
```

In C++ an abstract class is one with at least one pure virtual method (`= 0`); trying to create its object is a **compilation** error. JavaScript has no `abstract` keyword (TypeScript has), so the check is imitated by hand.

## 14.7 Class Methods and Static Methods

**Python**

```python
class Student:
    count = 0

    def __init__(self, name):
        self.name = name
        Student.count += 1

    @classmethod
    def from_string(cls, s: str):       # an alternative constructor
        return cls(s.strip())

    @classmethod
    def total(cls) -> int:
        return cls.count

    @staticmethod
    def is_valid_grade(score: int) -> bool:   # needs neither self nor cls
        return 0 <= score <= 100
```

**C++**

```cpp
class Student {
public:
    inline static int count = 0;

    Student(string name) : name(move(name)) {
        count++;
    }

    // an alternative constructor (a static factory method)
        size_t b = s.find_first_not_of(' '), e = s.find_last_not_of(' ');
        // counterpart of s.strip()
    }

    static int total() { return count; }

    // needs no object
        return 0 <= score && score <= 100;
    }

    string name;
};
```

**JavaScript**

```javascript
class Student {
  static count = 0;

  constructor(name) {
    this.name = name;
    Student.count += 1;
  }

  // an alternative constructor
    // this here is the class itself (like cls)
  }

  static total() {
    return this.count;
  }

  // needs no object
    return 0 <= score && score <= 100;
  }
}
```

| | First parameter | Access |
|---|---|---|
| instance method | `self` | attributes of the object and the class |
| `@classmethod` | `cls` | class attributes only |
| `@staticmethod` | none | nothing — just a function in the class |

C++ and JavaScript distinguish only an instance method and a **static** method (`static`): there is no separate `@classmethod`. In a static method of JavaScript `this` refers to the class itself (just like `cls`).

## 14.8 dataclass — Less Boilerplate

**Python**

```python
from dataclasses import dataclass, field


@dataclass
class Student:
    name: str
    group: str
    grades: list[int] = field(default_factory=list)

    def average(self) -> float:
        return sum(self.grades) / len(self.grades) if self.grades else 0.0


s = Student("Koval", "CS-21")
print(s)          # Student(name='Koval', group='CS-21', grades=[])
```

**C++**

```cpp
struct Student {
    string name;
    string group;
    // empty by default: Python's trap does not exist

    double average() const {
        return grades.empty() ? 0.0
                              : accumulate(grades.begin(), grades.end(), 0.0) / grades.size();
    }

    // C++20: == is generated automatically
};

Student s{"Koval", "CS-21"};                            // aggregate initialization
```

**JavaScript**

```javascript
class Student {
  constructor(name, group, grades = []) {
    Object.assign(this, { name, group, grades });
  }

  average() {
    return this.grades.length === 0
      ? 0
      : this.grades.reduce((p, q) => p + q, 0) / this.grades.length;
  }
}

const s = new Student("Koval", "CS-21");
console.log(s);   // Student { name: 'Koval', group: 'CS-21', grades: [] }
```

In C++ the counterpart of `dataclass` is a plain `struct` (constructor via braces, `== default` comparison since C++20). The Python `print(s)` corresponds to `console.log(s)` in JavaScript; in C++ you have to write the `<<` operator yourself.

`@dataclass` automatically creates `__init__`, `__repr__`, `__eq__`.

## 14.9 Common Mistakes

| Mistake | Correct |
|---------|---------|
| a forgotten `self` in a method | `def m(self):` |
| `self.x` without assignment in `__init__` | initialize all attributes |
| a mutable class attribute: `grades = []` | `field(default_factory=list)` |
| a forgotten `super().__init__()` | call it in the inherited constructor |
| `__str__` with `print` instead of `return` | return a string |
| C++: `virtual` forgotten in the base class | `virtual` in the base and `override` in the derived classes |
| C++: non-virtual destructor in the base class | `virtual ~Base() = default;` |
| JS: calling a constructor without `new` | `new Student(...)` |
| JS: losing `this` (`const f = s.addGrade; f()`) | `s.addGrade.bind(s)` or an arrow function |
| JS: `this` before `super(...)` in a derived class | call `super(...)` first |
